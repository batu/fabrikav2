Answer first: does production read Firebase Remote Config?

No Find the Bird production runs on static defaults.
  • games/find_the_bird/src/sdk/SdkContext.ts builds the Firebase provider on native iOS and never reads VITE_FTD_DISABLE_REMOTE_CONFIG (the flag in .env is dead for FTB; FTD reads it).
  • games/find_the_bird/src/analytics/firebaseApp.ts is a stub: getFirebaseApp() returns null. The provider throws "Firebase app is unavailable" and REMOTE_CONFIG_DEFAULTS win. On the phone the snapshot reports state: "fetch-failed".
  • The release lane's custody env does set the Firebase keys and VITE_FTD_DISABLE_REMOTE_CONFIG=false; that changes nothing for FTB.
Consequence: the §6 interstitial test is a build-per-arm test today. Making it a config experiment needs a small code change first (port FTD's firebaseApp.ts, FTD commit 12d018d08) plus a store build; recommended before the second experiment, not the first.

Proposal for the first experiment

Hypothesis: the interstitial after the third completion is where the 3 → 4 drop happens.

Read the week before choosing the arm. Because PR #76 already removes session-1 automatic ads for new installs, the first week of 1.2.5+ data is itself a comparison: new users' third completion in session 1 will log interstitial_gate reason=first_session (no ad), while returning-session completions log cadence + ad_lifecycle shown. Compare "users starting L4 / users completing L3" between those two groups and against the 69 → 51 baseline.

  • If the drop closes for first_session users: the ad is the cause. Arm A (build): raise interstitialMinLevel to 6 for all sessions vs control (default). Two store builds, since Remote Config is not read. Success: L3→L4 continuation and D1 retention of the exposed cohort; guard: interstitials per DAU and AdMob revenue per DAU reported side by side.
  • If the drop persists without an ad: the completion screen is the suspect. Look at level_complete_action on L3: long dwell_ms, background, dismissed_by_shutdown, and reward_revealed=false. Arm B (build): shorten the coin reveal (4200 ms → 1200 ms, the core default) or auto-advance; same metrics.
  • If next_level_ready.gap_ms is large or missing after L3: the level-4 load is the suspect (CDN level); check level_abandoned on L4 and the prefetch change in PR #77.

Before any config experiment: port FTD's firebaseApp.ts so FTB reads Remote Config; then experiment_exposure and the reveal-vs-pickup pattern apply as the handoff describes.
