# Regen-50 track record — 3×3 flash + neighbor suppression (2026-08-06)

What this run is: re-cut sprites for all 53 wave-1 levels with
`FTD_FLATKEY_MODEL=gemini-3.1-flash-image-preview` (3×3 batched) after landing
neighbor suppression (`_neighbor_free_crop`: aligned clean bg pasted over
every other bird's padded box, feathered, before the model call) and the
runtime minimum tap radius (38@2688, floor beats the neighbor clamp).

## What works (verified by looking)

- **Cotswolds (7px pair — worst case)**: before/after sprite sheets show the
  chalkboard, baskets, and window-frame scenery gone from sprites; the
  stacked pair resolved into separate clean birds.
- **Hawaii rainforest**: the bluebird's mossy rock is gone; remaining props
  are small held/worn items (flower stalk, leaf perch) which FLAT_PROMPT
  deliberately preserves.
- Suppression guard tests: neighbor erased, subject intact, no-clean-bg
  degrades to plain crop, far neighbors leave crops byte-identical.
- Tap-radius floor guard tests incl. floor-beats-clamp for very close pairs.

## What doesn't / known limits

- **Genuinely overlapping bodies** (touching, not just close) can still share
  one sprite — box-erase can't separate them. Follow-up if it matters:
  erase by the neighbor's local-diff component instead of its box.
- Model keeps "held" props liberally (a branch that reads as a baseball bat,
  ornamental flowers). Cosmetic; judged acceptable 2026-08-06.

## Ops lessons re-confirmed this run

- FTD_FLATKEY_MODEL must be set in the BACKEND environment (run-backend.sh
  launch), not the CLI shell — the CLI is an HTTP client. (Cost $1.15 to
  learn on 08-06 morning.)
- The repair rung (`materialize --force → recenter → approve`, retry once)
  runs inline per level now instead of as an after-pass.

## Defect class found post-batch: small-detection grid poisoning

Final spot-check zoomed the smallest sprites: several were PROP-ONLY
(a backpack without its bird, basket fragments, a door corner) while the
painted scene at those hitboxes showed complete, beautiful birds. Root
cause: detections under ~110px thumbnail into 3x3 grid cells too small to
read; the model recreates the most salient object and flat_ok cannot tell a
satchel from a bird. Stage-3's pot-stack sprite = same class.
FIX (2026-08-06): detections <110px bypass the grid — 2x-upscaled
neighbor-free crop through the single judge-gated call. 5 affected levels
re-cut for verification (morning market, dock hideout, bergen, lantern
canal, stockholm).
Lesson: the smallest-N-sprites zoom is a better audit instrument than
whole-sheet eyeballing — add it to every future cutout batch.

## Root cause resolved: provider-key starvation, not pipeline logic

The fragment epidemic had THREE candidate causes; instrumented elimination:
1. strip_flat_rim eating light birds — DISPROVED by a stage-by-stage dump
   (clean wren through every stage).
2. Small-det grid poisoning — real but secondary (the backpack case).
3. **OpenRouter key hit its WEEKLY limit mid-final-batch** — 403s degraded
   grid calls through the fail-soft chain while every level printed OK.
   Confirmed: same code + healthy key = 13/15 clean smallest-sprites.
Fixes shipped: small dets (<110px) route to the free extractor (deterministic
subject); materialize returns pendingCount/flatkeyCount/degradedToFreeChain
and logs batch degradation; the re-cut driver HALTS on degradation instead
of continuing. Full-catalog smallest-3 audit sheet is the standing
instrument (159 tiles, one image, catches everything the pretty sheets hide).
